1. Цель и выбранный сервис

Создан Telegram-бот с режимами объяснения программирования, перевода и проверки знаний. Бот передаёт модели системную инструкцию и историю текущего чата, сохраняет успешные пары вопрос-ответ в PostgreSQL и обрабатывает отказы внешних сервисов.

API: OpenRouter, https://openrouter.ai/api/v1/chat/completions. Модель предоставленного эксперимента: cohere/north-mini-code:free; формат OpenAI-совместимый Chat Completions, v1. Telegram обслуживается через aiogram 3.31.0. В исходном отчёте указан запуск 13.10 на macOS 26.2 с Python 3.12. Новая проверка выполнена 17.10 на macOS с Python 3.12.14; повторные вызовы внешней LLM в неё не входили.

Обработчики: app/handlers/assistant.py; сценарии: app/assistant.py; SQL: app/storage.py; HTTP-клиент: app/llm.py; инструкции: app/prompts.py; контекст: app/history.py. LLM-клиент и хранилище подменяются в функциональных тестах.

lab1_profiles хранит chat_id, активный режим и temperature. lab1_turns хранит вопрос и ответ, id и время. Каждая выборка ограничена chat_id. Полная пара сохраняется одной транзакцией после успешного ответа модели. /reset очищает историю своего чата; режим и temperature сохраняются. Смена режима очищает историю.

По умолчанию сохраняются 20 сообщений (10 пар): достаточно для нескольких уточнений и ограничивает объём хранения. Оценка: UTF-8 байты плюс 16 единиц на сообщение. Бюджет 24000 выбран ниже заявленного окна отбираемых мастером моделей. В эксперименте max_tokens=8000, бюджет входа - 16000; по умолчанию max_tokens=1200. Старые пары удаляются целиком; инструкция, few-shot и текущий вопрос сохраняются. Для другой модели лимит нужно сверить с её окном. Оценка не заменяет tokenizer.

5. Анализ качества и вариативности

В этой выборке текстовое сходство последовательно снизилось с 30.0% при t=0.0 до 15.0% при t=1.0. Это среднее трёх попарных коэффициентов SequenceMatcher с настройками по умолчанию внутри каждой группы. Метрика сравнивает последовательности символов, зависит от длины и особенностей алгоритма; она не измеряет смысл или правильность ответа.

Даже при t=0.0 ответы не были идентичными: длины 1348, 1460 и 1415 символов, разные контрольные вопросы и акценты. Поэтому обещать полную детерминированность при нулевой temperature нельзя. Seed не фиксировался; различия провайдерной инфраструктуры и вычислений здесь не исследовались.

Длина не росла монотонно: средние 1407.7, 1256.0, 1304.0 и 1416.7 символа. Нумерация соблюдена в 11 из 12 ответов. В №1 появилась дополнительная нумерация 1-2 в контрольном задании. Во всех ответах основное различие изменяемости объяснено, однако это не исключает ошибок в деталях.

Проверка конкретных неточностей

№5 (t=0.3): утверждение «кортеж всегда заканчивается запятой» неверно. (1, 2) уже является кортежем; обязательная запятая нужна для записи одного элемента (1,). В №11 (t=1.0) сказано обратное ошибочное правило: у одноэлементного кортежа запятую якобы можно опустить.

№8 (t=0.7): попытка colors.append(...) вызывает AttributeError, а не указанный TypeError. TypeError возникает при присваивании элементу кортежа. №10 (t=1.0): предложение об одинаковых квадратных скобках противоречит следующей фразе и собственному примеру; есть вставка once и языковая неточность.

Во многих ответах хешируемость кортежа объяснена только неизменяемостью. Нужное уточнение: кортеж может быть ключом словаря, если все его элементы хешируемы. Например, кортеж со списком не хешируется. Утверждения о безусловном преимуществе скорости не подтверждены измерениями в этой работе.

type((1)).__name__       # int
type((1,)).__name__      # tuple
(1, 2).append(3)         # AttributeError
hash(([1],))            # TypeError: unhashable type: list

Эти небольшие контрпримеры проверены при подготовке отчёта в Python 3.12. Сверка правил: docs.python.org/3.12/tutorial/datastructures.html#tuples-and-sequences и docs.python.org/3.12/library/stdtypes.html#immutable-sequence-types.

Выбор настройки

Для режима /study предварительно выбран t=0.3: в трёх запусках соблюдена нумерация и получена наименьшая средняя длина. Ответ №1, temperature=0.0
**Прямой ответ (три ключевых различия)**

1. **Изменяемость** – Элементы списка можно добавлять, удалять или изменять после его создания, в то время как кортеж является *неизменяемым*: после определения его элементы нельзя изменить.
2. **Синтаксис** – Списки записываются с использованием квадратных скобок `[ ]`, например `my_list = [1, 2, 3]`. Кортежи используют круглые скобки `( )` (или запятую без скобок), например `my_tuple = (1, 2, 3)`.
3. **Использование и производительность** – Поскольку кортежи неизменяемы, они немного быстрее в обработке и могут использоваться в ситуациях, когда вам нужно "зафиксировать" набор данных (например, в качестве ключа словаря). Списки лучше подходят для последовательностей, которые вам нужно изменять.

**Небольшой пример**

```python
# Список (изменяемый)
my_list = [10, 20, 30]
my_list[1] = 99          # работает: my_list теперь [10, 99, 30]

# Кортеж (неизменяемый)
my_tuple = (10, 20, 30)
# my_tuple[1] = 99       # TypeError: 'tuple' object does not support item assignment
```

1. **Изменяемость** – список можно изменять (добавлять, удалять или изменять элементы), а кортеж — нет. Изменение кортежа после создания вызовет ошибку.
2. **Синтаксис обозначения типов** – списки обозначаются квадратными скобками `[ ]`, а кортежи — круглыми скобками `( )` (запятую можно опустить, если в кортеже один элемент).
3. **Типичная область применения** – используйте список, когда вам нужно изменить коллекцию данных; используйте кортеж для неизменяемых «записей данных» или словаря с ключами в Python.

**Небольшой пример**

```python
# Список (изменяемый)
fruits = ['apple', 'banana', 'cherry']
fruits.append('date')          # OK – теперь в fruits есть четыре элемента
fruits[1] = 'blueberry'        # OK – элемент изменён

# Кортеж (неизменяемый)
colors = ('red', 'green', 'blue')
# colors.append('yellow')    # AttributeError: 'tuple' object has no attribute 'append'
# colors[0] = 'orange'        # TypeError: 'tuple' object does not support item assignment
```
