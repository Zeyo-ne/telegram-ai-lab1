`RUN_INTEGRATION=1`. Проверки с подменой Telegram и LLM не заменяют показ живого бота.

## Запуск на macOS

Откройте **НАЧНИ-ЗДЕСЬ.html** — подробную инструкцию.
Нужны Python 3.12 и работающий Docker Desktop. При установленном Homebrew:

```bash
brew install python@3.12
bash scripts/mac.sh run
```

Можно дважды щёлкнуть **Запустить.command**. Если файл не открывается, используйте
команду выше в Терминале из папки проекта. Системные защиты macOS отключать не нужно.
Мастер спросит токен Telegram, необязательный Telegram-прокси, ключ OpenRouter и модель.
Список бесплатных моделей с temperature загружается в момент настройки.
Файл .env остаётся локальным; не публикуйте его.

Остановка: Control+C. PostgreSQL хранит историю в Docker volume.
Не переносите настроенную папку без резервной копии БД: имя volume зависит от пути.

## Возможности

- Личные текстовые чаты; остальные типы сообщений игнорируются.
- `/start`, `/help`: справка без LLM.
- `/study`: объяснение программирования, режим по умолчанию.
- `/translate`: перевод на указанный язык, два few-shot-примера.
- `/quiz`: вопрос по теме, проверка ответа и следующий вопрос.
- Смена режима атомарно сохраняется и очищает свою историю.
- `/settings`: просмотр настроек; `/settings 0.7` меняет temperature своего чата.
- `/reset`: очищает свою историю, сохраняя режим и temperature.
- История и настройки восстанавливаются из PostgreSQL после перезапуска.
- Контекст сокращается целыми парами, инструкции и текущий запрос сохраняются.
- Typing-индикатор, безопасные ошибки, ограниченные повторы временных сбоев.
- Длинные ответы отправляются по порядку без разметки, с учётом UTF-16 и emoji.

## Структура

| Файл | Назначение |
|---|---|
| app/handlers/assistant.py | Telegram-команды и отправка |
| app/assistant.py | Сценарии, последовательная обработка сообщений одного чата |
| app/storage.py | Схема, транзакции, параметризованные SQL-запросы |
| app/llm.py | OpenAI-совместимый Chat Completions HTTP-клиент |
| app/prompts.py | Три системные инструкции и примеры |
| app/history.py | Ограничение контекста и разделение сообщений |
| app/config.py | Проверка настроек |
| scripts/experiment.py | Независимые реальные запросы |
| scripts/report.py | Отчёт из фактических результатов |

Таблицы lab1_profiles и lab1_turns создаются при запуске через идемпотентный DDL
с advisory lock. Обычные операции не удаляют чужие данные.
Пара вопрос–ответ сохраняется транзакцией; при ошибке модели ответ не записывается.

## Настройки

Все параметры перечислены в .env.example. Обязательны LLM_API_KEY и LLM_MODEL.
LLM_BASE_URL — адрес API без /chat/completions, по умолчанию OpenRouter.
Для стороннего сервиса задайте его OpenAI-совместимый адрес в .env до запуска мастера.
Telegram-прокси не применяется к API модели: доступ к нему проверьте отдельно.

HISTORY_MAX_MESSAGES=20 сохраняет 10 полных пар; нечётные значения округляются вниз.
CONTEXT_MAX_UNITS=24000 — оценка: UTF-8 байты + 16 на сообщение, с резервом
LLM_MAX_TOKENS=1200 для ответа. Это консервативная эвристика, не точный tokenizer.
Выберите лимит ниже окна модели и проверьте реальный запрос.
INPUT_MAX_CHARS=12000 ограничивает ввод. Не помещающийся текущий вопрос
отклоняется до API и не обрезается.

LLM_TIMEOUT=60 ограничивает весь вызов, LLM_RETRIES=1 допускает один повтор
сетевой ошибки, HTTP 429 или 5xx. Авторизация не повторяется.
OpenRouter получает provider.require_parameters=true для поддержки temperature.
Оборванный ответ не сохраняется как успешный.

## Проверки

Дважды щёлкните **Проверить.command** или выполните:

```bash
bash scripts/mac.sh tests
```

Проверки не обращаются к настоящим Telegram и LLM.
HTTP-тесты используют локальный управляемый сервер.
Фактический вывод сохраняется в reports/checks.json.
Реальная PostgreSQL проверяется отдельными Docker-тестами:

```bash
RUN_INTEGRATION=1 .venv/bin/python -m pytest -m integration -v
```

Они создают отдельные тестовые контейнеры/volume и очищают только их.
GitHub Actions проверяет Ubuntu, Windows, macOS; на Ubuntu также Docker.

## Эксперимент и отчёт

**Эксперимент.command** или `bash scripts/mac.sh experiment` делает 12 вызовов:
по три для 0.0, 0.3, 0.7, 1.0. Перед каждым очищается отдельная история
через тот же сценарий, что /reset. Затем два вызова сравнивают неполную
и улучшенную инструкции. Вызовы идут к выбранной модели и используют её лимиты.

Результаты: reports/experiment.json, experiment.csv, lab1-report.html.
При сбое уже полученные ответы остаются сохранёнными со статусом partial.
Проверьте ответы, заполните анализ и ФИО. HTML редактируется кликом по зелёным полям;
правки сохраняются отдельной кнопкой, PDF — через печать.
Повторная генерация заменяет несохранённые ручные правки.

Для сдачи покажите три режима, разделение двух настоящих пользователей,
сохранность после перезапуска, сбой API и длинный ответ.
Проверенную сдаваемую версию отметьте тегом lab1 и добавьте отчёт в репозиторий.
Комплект подготовлен при помощи OpenAI Codex; помощь AI укажите в отчёте.

## Ограничения

Один polling-процесс на токен. Доступность моделей и лимиты могут меняться.
История записывается до отправки Telegram: при отказе доставки ответ может остаться в БД.
Оценка контекста не заменяет tokenizer. Резервное копирование — отдельно.
История не пишется в логи, но хранится в локальной БД без отдельного шифрования приложения.
