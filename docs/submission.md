## Что входит в сдаваемую версию

- `submission/lab1-report.pdf` и HTML-версия отчёта.

- `submission/checks.json`: новый вывод проверок с датой и кодами завершения.

- В сопроводительном ZIP: `submission/private/ai-review-transcript.txt`,
  фрагмент подлинных запросов текущей проверки. Он передаётся отдельно от открытого репозитория.

Отчёт ссылается на тег `lab1`. Перед передачей ссылки следует убедиться, что он
опубликован и указывает на эту версию. Не переназначайте уже опубликованный тег.

https://github.com/ai-in-sd-y29/telegram-ai-lab1-sazhin-m3216.

не восполняет её отсутствие. Предъявите первоначальную сессию отдельно, если она сохранилась.

## Запуск на другом компьютере

1. Установить Python 3.12 и Docker Desktop/Engine, запустить Docker.
2. На macOS выполнить `bash scripts/mac.sh run` из папки проекта. На Windows -
   команды раздела README «Другие платформы».
3. Ввести собственный токен учебного Telegram-бота и ключ OpenAI-совместимого API.
   Выбрать доступную модель с поддержкой temperature; доступность модели прошлого
   эксперимента не гарантируется. Для стороннего API сначала задать LLM_BASE_URL.
4. Проверить /start и обычный вопрос. Использовать один polling-процесс на токен.

Без ключей можно установить зависимости командой
`python3.12 scripts/bootstrap.py --dependencies-only`, затем запустить
`.venv/bin/python -m pytest -q` и проверки из README.
При работающем Docker команда
`RUN_INTEGRATION=1 .venv/bin/python -m pytest -m integration -v`
создаёт отдельные временные БД и проверяет их сохранность после перезапуска.
На Windows путь интерпретатора - `.venv/Scripts/python.exe`; переменную окружения
задают перед командой средствами PowerShell.

## Последовательность показа

1. Первый аккаунт: /start; /study; «Объясни список и кортеж в Python»;
   затем уточнение без повторения темы. Показать /translate и /quiz на настоящей модели.
2. Первый аккаунт: /settings 0.7. Второй аккаунт: /settings 1.0 и другой вопрос.
   Убедиться, что значения и история не пересекаются.
3. Остановить только процесс бота, не удаляя БД. Запустить снова из той же папки.
   На обоих аккаунтах показать /settings и продолжить каждый диалог.
4. Первый аккаунт: /reset; показать сохранение режима и temperature. На втором
   аккаунте продолжить прежний разговор. Затем сменить режим первого и проверить
   очистку его истории.
5. Показать длинный ответ модели и порядок частей. Заранее проверить запрос,
   вызывающий ответ больше 4096 символов, и достаточный LLM_MAX_TOKENS. Если модель
   не дала длинный ответ, этот живой сценарий ещё не подтверждён; автоматический
   тест разбиения текста показывается отдельно.
6. Показать обработку недоступности API и результаты управляемых HTTP-тестов.
   Неверный ключ можно проверить на отдельной конфигурации и затем восстановить её.
   Ключи не показывать в окне терминала, истории команд или снимках экрана.

## Что ещё требует участия студента

- Предъявить первичную историю разработки и объяснить свой вклад.
- Выполнить живой показ двух настоящих Telegram-аккаунтов и длинного ответа.
- Заранее отправить преподавателю ссылку на репозиторий в учебной организации.

Автоматические проверки постоянной БД подтверждают код сохранения и разделения
данных. Они не являются записью живой демонстрации в Telegram.
